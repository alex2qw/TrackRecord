# Privacy and responsible use

TrackRecord uses permitted public transport data to describe historical
service performance. It does not collect passenger identities, accounts,
payment details, precise personal journeys, or location history.

The project is motivated by a personal commute, but that commute is not stored
as a user record. Route context is documented as part of the project scope,
not linked to an individual account.

Metrics are descriptive summaries of the records available to the importer.
They are not guarantees, safety-critical advice, or predictions of a specific
future train. The dashboard should show the data period, sample size, source,
and coverage so that small or incomplete samples are not presented as
certainty.

Missing records and reporting differences can bias comparisons between
stations, operators, and time periods. A low reliability score does not prove a
single cause, and delay data should not be used to assign blame without
additional evidence.

Provider terms, attribution, retention rules, and redistribution permissions
must be checked before publishing a deployed instance or redistributing raw
payloads.
